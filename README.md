# Журнал иностранных студентов факультета права

## Основной сценарий: посещаемость по дате

Преподаватель выбирает сверху дату и дисциплину, затем отмечает список студентов по этой дисциплине: «Был», «Не был» или «Нет данных», и нажимает «Сохранить». Дисциплины берутся из связей реестра «преподаватель – студент – дисциплина». РУЗ для этого не требуется; фоновое обновление расписания можно отключить через `AUTO_SYNC=false`. Запись привязана к преподавателю, дисциплине, студенту и дате; версия считается отдельно по каждой дисциплине. Конфликт изменений из разных окон возвращает 409 без перезаписи. Таблицы прежней версии без дисциплины переименовываются в `daily_marks_v1` и `daily_revisions_v1`, записи переносятся с пустой дисциплиной.

В разделе «Обзор» руководство выбирает период. Хотя бы одна явка даёт «Был хотя бы раз», только отрицательные ответы – «Присутствие не отмечено», отсутствие ответов – «Нет данных». Доступны последнее посещение, история ответов с преподавателями, поиск, фильтр и CSV для Excel. Старые отметки из журнала занятий включаются в историю. Старые показатели и процедуры сохранены в разделе «Студенты»; дневные ответы не используются для автоматического вывода об отсутствии семь учебных дней.

На Mac храните рабочую базу и исполняемую копию приложения вне синхронизируемых iCloud папок. `DB_PATH` и `BACKUP_DIR` позволяют указать локальные пути; `.env` и данные не включаются в репозиторий.

## Запуск

Репозиторий содержит исходники. Реестр студентов, расписание, базы, резервные копии и `.env` хранятся отдельно и не публикуются. После клонирования создайте папку `work/`, импортируйте свой реестр командой `uv run --with openpyxl python scripts/import_roster.py /path/to/source.xlsx` или восстановите закрытый `data/roster.json`. Для входа руководства настройте `MANAGEMENT_PASSWORD_HASH` в `.env`.

Node.js 24. Установить зависимости `npm ci`, затем `npm run dev`. Локальный адрес: http://127.0.0.1:3100. Тестовая база хранится отдельно в `data/demo.sqlite`.

Для FirstVDS: [инструкция](deploy/FIRSTVDS.md) и [развёртывание](deploy/DEPLOY.md).

## Вход и ответственность

Выбор роли и имени без университетской авторизации: `AUTH_MODE=selection`. В локальном режиме используется по умолчанию; для рабочего режима указан в `.env.example`. Это выбор рабочего кабинета, не подтверждение личности. Преподаватели выбирают имя без пароля. Обе роли руководства дополнительно требуют общий пароль из MANAGEMENT_PASSWORD_HASH (scrypt); при отсутствии хеша доступ закрыт. Общий пароль подтверждает знание пароля, но не личность выбранного сотрудника. Для ограничения круга посетителей нужен отдельный сетевой доступ на сервере. Журнал изменений фиксирует выбранное имя, не удостоверенную личность.

Преподаватель видит свои пары с импортированными студентами и ставит явку. Менеджер учебного офиса видит общую статистику и реестр, редактирует процедуры только своего курса и программы. Руководство центра редактирует распределение и все процедуры. Возможности ролей проверяются сервером; выбор чужой роли при этом остаётся доступен по принятой модели входа.

Справочник `src/office.js`: десять сотрудников, распределение по [контактам ЦУУП](https://pravo.hse.ru/centre/contact), сверено 16.09.2026. Руководству в приложении предоставлен общий доступ как проектное решение. Вспомогательный персонал не добавлен как менеджеры программ. Изменение реального распределения требует обновления справочника и перезапуска.

## Контингент и дашборд

Основной лист Excel содержит 179 уникальных написаний ФИО студентов, 424 преподавателя и 2704 связи. Это ещё не подтверждённый полный реестр иностранцев факультета. В карточке руководство указывает программу, курс, иностранный статус и статус обучения. Менеджер назначается автоматически по программе и курсу, без угадывания по ФИО или группе.

Общая статистика охватывает всех подтверждённых действующих иностранных студентов загруженного реестра, независимо от наличия расписания и отметок. Фильтры таблицы не меняют статистику факультета. Непроверенные записи видны отдельно; отсутствие данных не означает отсутствие проблемы. Для полной статистики факультета нужен полный подтверждённый реестр.

Два независимых списка: отсутствие 7 учебных дней и просроченные процедуры. Пересечение – отдельный фильтр. Семь дней считаются по разным датам с явным пропуском после последней явки. Несколько пар в день считаются один раз; явка хотя бы на одной паре дня сбрасывает последовательность. Неотмеченное занятие не считается пропуском.

## Добавление студента

Руководство (роль admin) добавляет иностранного студента, которого нет в импортированном реестре: кнопка «Добавить студента» в разделах «Обзор» и «Студенты». Обязательны ФИО и хотя бы одна связь «преподаватель – дисциплина»; программа, курс, статус контингента и гражданство заполняются сразу, остальное – в карточке. Студент появляется в дневном журнале указанных преподавателей по указанным дисциплинам. Добавления хранятся в таблице `roster_additions` и переживают перезапуск и повторный импорт реестра; ID производится от ФИО так же, как при импорте, поэтому позднее появление того же ФИО в Excel не создаёт дубля. Повторное ФИО отклоняется с 409. Менеджер (роль office) добавлять студентов не может.

## Процедуры

Проверки миграционного учёта, визы/пребывания, медосвидетельствования, дактилоскопии/фотографирования, страхования. Это перечень для проверки применимости сотрудником, не универсальное назначение обязанностей всем иностранцам. Учтены [сервисы поддержки](https://istudents.hse.ru/) и [инструкции визового центра](https://ivisa.hse.ru/medst).

Статусы: нет данных, не выполнено, на проверке, подтверждено, не требуется. Сотрудник задаёт срок после проверки основания пребывания, гражданства и даты въезда. Подтверждение требует даты выполнения, освобождение – пояснения. Просрочка вычисляется по сроку невыполненной процедуры, истечение – по сроку действия подтверждения. Переданные на проверку документы отображаются отдельно. Система не выносит юридических решений.

Повторный въезд, изменение основания пребывания и истечение документов требуют повторной проверки сотрудником. Автоматической интеграции с HSE App X и МВД нет. Диагнозы, анализы и сканы документов здесь не собираются. Сервисные вопросы (пропуск, связь, адаптация) не создают процедурный долг.

Прежние учебные задолженности сохранены отдельно для совместимости и не включаются в процедурные показатели. CSV содержит отдельные столбцы для этих двух направлений.

## Автоматизация

РУЗ обновляется фоновой постоянной очередью, интервал по умолчанию 6 часов; ошибки приводят к повтору, сохранённая история остаётся. Загружается окно ±7 дней; пары без студентов импортированного списка скрыты. Изменённые и исчезнувшие пары с отметками сохраняются для проверки. Сопоставление по точному преподавателю, дисциплине и группе. У одного человека в РУЗ бывает несколько карточек с одинаковым ФИО (person и lecturer): расписания всех карточек объединяются без дублей, карточки с пустым ответом пропускаются; все ID карточек хранятся в `teacher_links` через запятую. Ошибка сопоставления остаётся только при полном отсутствии точного совпадения.

Журнал сохраняется автоматически. Версии защищают от перезаписи правок второй вкладки. Открытая сводка обновляется раз в 30 секунд. SQLite копируется при старте и каждые 24 часа при `AUTO_BACKUP=true`; внешнее резервирование и ротацию настраивает владелец сервера.

## Обновление состава

После резервной копии и остановки приложения: `uv run --with openpyxl python scripts/import_roster.py /path/to/source.xlsx`. Импорт заменяет `data/roster.json`; перезапустить сервер. Написания «Вак_Фамилия» и «Фамилия» в одном файле считаются одним преподавателем и сливаются в написание без приставки; одиночные «Вак_» остаются как есть, потому что в РУЗ они так и значатся. ID сейчас производятся из точного ФИО, поэтому изменение написания требует миграции. Новые студенты, переводы и гражданство автоматически из РУЗ не получаются. Данные программы/курса можно передать в реестре полями `program`, `year`, `foreignStatus`, `enrollmentStatus`; сохранённая карточка имеет приоритет над импортом.

## Публичное зеркало

GitHub Pages перенаправляет посетителей на временный защищённый HTTPS-адрес приложения. Сайт работает на Mac владельца; компьютер должен оставаться включённым и подключённым к интернету. Внешний вход закрыт отдельным общим паролем, руководство дополнительно защищено своим паролем. Это временный доступ, не постоянный хостинг.

` scripts/access-proxy.mjs ` слушает только 127.0.0.1:3112, проверяет пароль, отклоняет запросы на изменение с постороннего origin и передаёт разрешённые запросы приложению на 127.0.0.1:3100. Файл конфигурации задаётся через ACCESS_CONFIG и не публикуется. Данные и пароли не входят в репозиторий. При остановке туннеля внешний адрес недоступен.
