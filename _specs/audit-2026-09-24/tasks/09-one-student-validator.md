# 09: Один валидатор полей студента, одна функция идентификатора

**Статус:** done

**Блокируется:** ничем (можно брать сразу).

**Закрывает критерии:** К10, К12.

## Что построить

Допустимые значения и длины полей студента (проживание, нахождение в РФ, статус контингента, текстовые поля) заданы в одном месте рядом с политикой полей студента, и маршруты сотрудника и студента вызывают один валидатор: на одинаковый недопустимый ввод – одинаковая ошибка. Идентификатор студента по ФИО вычисляет одна функция приложения; проверка ФИО при добавлении студента идёт тем же путём, что при правке реестра. Python-скрипты импорта получают комментарий-ссылку на эту функцию и не переписываются.

## Критерии приёмки

- [x] Сначала тест: одинаковый недопустимый ввод (недопустимое проживание, слишком длинное поле) через правку сотрудником и через кабинет студента даёт одинаковый статус и одинаковый текст ошибки.
- [x] Перечни значений и длины определены один раз; копии удалены.
- [x] Вычисление идентификатора студента по ФИО – одна функция; все места в src используют её; идентификаторы существующих студентов не меняются (тест на известное ФИО → известный id).
- [x] Добавление студента с ФИО короче 3 или длиннее 150 символов и с дублем без учёта регистра отклоняется так же, как при правке реестра.
- [x] Поля, которые студенту править нельзя, по-прежнему нельзя (тесты кабинета проходят без изменения ожиданий).
- [x] Все тесты зелёные, prettier чист.
