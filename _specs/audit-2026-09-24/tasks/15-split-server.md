## Что построить

Главный файл сервера (≈1500 строк, меняется по восьми несвязанным причинам) разрезан по образцу уже существующих модулей `register…(app, deps)`: вход и сессии (включая OIDC и ограничение попыток), реестр (CRUD, импорт), схема базы и первичное наполнение (с разовыми миграциями), резервное копирование. В главном файле остаются конфигурация, заголовки безопасности, сборка приложения, обзор и карточка. Поведение не меняется.

## Критерии приёмки

- [ ] Перенос без изменения поведения: каждый модуль – отдельный коммит «move … without behaviour change», тесты не меняют ожиданий.
- [ ] Порядок подключения прослоек (проверка Host, Origin, разбор JSON, сессия) сохранён – тест заголовков и CSRF проходит.
- [ ] Разовые миграции и первичное наполнение перенесены целиком, ничего не удалено.
- [ ] Главный файл заметно короче (цель – меньше 700 строк); размер каждого модуля указан в отчёте.
- [ ] Итоговый замер на базе «год» не хуже, чем после задач 11–13.
- [ ] Все тесты зелёные, prettier чист.
