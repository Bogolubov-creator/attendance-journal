# 02: Шлюз считает попытки по реальному адресу соединения

**Статус:** done

**Блокируется:** ничем (можно брать сразу).

**Закрывает критерии:** К1.

## Что построить

Временный шлюз доступа (Basic-пароль перед журналом) перестаёт доверять заголовку X-Forwarded-For при подсчёте неверных паролей: ключ счётчика – адрес сокета. Перебор пароля с подменой заголовка упирается в 429 так же, как без неё. Формат конфигурации шлюза и его поведение для правильного пароля не меняются.

## Критерии приёмки

- [x] Сначала падающий тест: шлюз и заглушка приложения на свободных портах, 11 запросов с неверным паролем и разным X-Forwarded-For – 11-й получает 429.
- [x] Порт шлюза и адрес приложения можно задать переменными окружения; по умолчанию прежние значения (3112 и 127.0.0.1:3100), живой запуск владельца без изменений.
- [x] Правильный пароль по-прежнему проксирует запрос и снимает счётчик.
- [x] Хеш пароля и формат файла конфигурации не меняются.
- [x] Все тесты зелёные, prettier чист.

## Поправка по проверке

Проверяющий заметил: за туннелем адрес у всех один, а сброс счётчика верным паролем давал подбирающему по 9 попыток после каждого запроса сотрудника. Критерий «снимает счётчик» заменён: верный пароль проксирует запрос, но счётчик не снимает – попытки сгорают по окну 15 минут. Цена – любой может закрыть вход всем на 15 минут; шлюз временный, перебор важнее.
