# 06: День X – режим «только личные пароли»

**Статус:** done

**Блокируется:** 02, 03

**Закрывает критерии:** К15, К16, К17 (включение режима), К19

## Что построить

У полного доступа на странице «Сотрудники» – кнопка «Включить вход только по личным паролям». Она сначала показывает, у скольких сотрудников (преподавателей со студентами и сотрудников офиса) пароля ещё нет и что они потеряют доступ, и просит подтвердить. После подтверждения:

- вход выбором себя из списка с общим паролем отклоняется;
- демо-вход сотрудников отклоняется (рабочий сервер на Mac идёт в демо-режиме на живых данных – иначе это был бы обход);
- ответ о сессии до входа больше не содержит списков ФИО преподавателей и сотрудников офиса;
- сессии, выданные по общему паролю и демо-входом сотрудников, закрываются при следующем запросе;
- на экране входа остаётся только форма логина и пароля.

Флаг хранится в базе и переживает перезапуск. Снять его можно только отдельным серверным скриптом. До включения всё работает как раньше. Кабинет студента, его вход и демо-вход студентом режим не затрагивает. В README описывается порядок запуска для владельца: скрипт кода администратора → первый вход → массовая выгрузка → рассылка → наблюдение за колонкой «Доступ» → включение режима; и как снять режим скриптом.

## Критерии приёмки

- [x] Предпросмотр показывает число сотрудников без пароля; включение требует подтверждения; включать может только полный доступ (К15).
- [x] После включения вход выбором из списка и демо-вход сотрудников отклоняются, ответ о сессии не содержит ФИО сотрудников, прежние сессии по общему паролю закрыты (К15).
- [x] После перезапуска сервера режим остаётся включённым; серверный скрипт снимает его, и прежний вход снова работает (К15).
- [x] До включения вход выбором из списка и общим паролем работает как раньше; существующие тесты проходят без изменений (К16).
- [x] Включение режима пишется в журнал изменений (К17).

## Заметка исполнителя

Экран входа собирается в `app.js`, который в jsdom не поднимается. Поэтому скрытие прежней формы после дня X проверено в headless Chrome на временной базе: до включения блок прежнего входа и список ФИО есть в разметке, после – блок скрыт (`hidden`), списка нет. В jsdom проверено окно подтверждения.
