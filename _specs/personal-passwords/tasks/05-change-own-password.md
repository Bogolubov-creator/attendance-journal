# 05: Смена своего пароля

**Статус:** done

**Блокируется:** 02

**Закрывает критерии:** К3 (при смене пароля), К14, К17 (смена пароля)

## Что построить

В меню под именем сотрудника, вошедшего по личному паролю, – пункт «Сменить пароль». Форма: текущий пароль, новый, повтор. Без верного текущего пароля смена не проходит. Новый пароль проверяется по тем же правилам, что при первом входе. После смены прочие сессии этого сотрудника закрываются, а текущее устройство остаётся в журнале. Сотруднику, вошедшему по общему паролю, пункт не показывается.

## Критерии приёмки

- [x] Смена с неверным текущим паролем отклоняется, пароль не меняется (К14).
- [x] Новый пароль короче 10 символов или из списка распространённых отклоняется (К3).
- [x] После смены старый пароль не принимается, новый – принимается; другая сессия того же сотрудника закрыта, текущая продолжает работать (К14).
- [x] Неверный текущий пароль учитывается в счётчике блокировки учётной записи.
- [x] Смена пишется в журнал изменений без паролей (К17).
- [x] Пункт меню и форма проверены в jsdom; при входе по общему паролю пункта нет.

## Заметка исполнителя

Пункт меню проверен так: в jsdom проверено окно смены пароля, на сервере проверен отказ 403 при входе по общему паролю. Сама разметка боковой панели живёт в `app.js`, который в jsdom не поднимается; условие показа пункта – `user.source === "personal"`.
