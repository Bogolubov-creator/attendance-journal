# 05: Установка на удалённый Linux-сервер по SSH

**Статус:** done

**Блокируется:** 02, 04

**Закрывает критерии:** К2 (удалённо), К3 (SSH и удалённые проверки), К8, К14 (SSH)

## Что построить

Ответ «На удалённый Linux-сервер по SSH» спрашивает адрес, пользователя, порт (22), путь к ключу и папку установки; пароль SSH, если нужен, спрашивает сам SSH. Проверки до изменений: сервер отвечает по SSH, это Linux, есть Docker и Compose и права пользователя на Docker, свободны порты 80 и 443 при встроенном Caddy; есть ли в папке прежняя установка (тогда – «Обновить»/«Выйти» из таски 04). Код уезжает архивом только из файлов репозитория (`git archive`, без git – `tar` по списку файлов приложения); `.env` передаётся через стандартный ввод SSH с правами 600, без временного файла и аргументов. На сервере – папки, `docker compose config`, сборка и запуск, `/healthz`, при неудаче – последние строки журнала; затем включение режима личных паролей, первый код и памятка из таски 02 – всё через SSH.

## Критерии приёмки

- [x] Нет SSH-доступа, не Linux, нет Docker или прав на него, занят порт – сообщение и остановка до изменений (К3, К14).
- [x] В архиве только файлы репозитория: нет `.env`, баз, выгрузок, копий, папок данных (К8).
- [x] `.env` уходит на сервер через стандартный ввод SSH, секретов нет в аргументах команд (К8).
- [x] Удалённо только Docker; план команд на сервере – папки, проверка, запуск, `/healthz`, режим входа, первый код (К2).
- [x] Прежняя установка на сервере – «Обновить» с копией базы, данные не тронуты.

## Заметка исполнителя

- Папки данных на сервере отдаются пользователю контейнера (UID 1000) через `docker run … chown`, без sudo: достаточно прав на Docker.
- Здоровье на сервере – по статусу проверки Compose (`docker compose ps … Health`), она сама ходит на `/healthz` с правильным Host.
- Архив – `git archive HEAD -- <файлы приложения>` (только закоммиченная версия), без git – `tar` по тому же списку; `data/.gitkeep` в архив не попадает, иначе обновление упёрлось бы в права папки данных.
- Каждая команда SSH – отдельное соединение: при входе по паролю SSH спросит его несколько раз; удобнее ключ. Живой прогон на сервере не выполнялся – на машине разработчика нет Linux-сервера с Docker.
