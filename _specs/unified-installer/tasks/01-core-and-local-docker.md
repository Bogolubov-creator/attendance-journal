# 01: Ядро установщика и установка через Docker на этот компьютер

**Статус:** done

**Блокируется:** ничем (можно брать сразу)

**Закрывает критерии:** К1 (обёртки в корне), К2 (этот компьютер через Docker), К3, К4, К6, К9, К10 (Docker), К11, К12, К14 (Docker, домен, порты, здоровье)

## Что построить

Человек запускает `./install.sh` (Linux, macOS) или `install.bat` (Windows) в папке журнала. Обёртка проверяет Node.js 24 (нет – подсказка, где взять, и остановка) и запускает ядро установщика на Node.js. Ядро задаёт вопросы по одному: у каждого пояснение и ответ по умолчанию, Enter принимает его, `<` возвращает назад с сохранёнными ответами. В этом срезе: «куда ставить» (удалённый вариант пока отвечает «будет в следующей версии»), «через Docker / без Docker» (без Docker пока «будет в следующей версии»), домен, встроенный Caddy или свой прокси (для своего – `TRUST_PROXY` и предупреждение про Host), папки базы, копий и сканов, число копий, сводка без секретов и «Установить?».

До изменений – проверки: папка журнала, Docker и Compose, свободные порты 80 и 443 при встроенном Caddy. Ошибка – понятное сообщение и остановка без изменений.

После подтверждения: `.env` с доменом, `APP_ORIGIN` на https, `DEMO_MODE=false`, `DATA_MODE=live`, `TRUST_PROXY`, копиями и путями папок, права 600 (Windows – доступ администраторам и системе); значения с переводом строки и пустые обязательные отклоняются до записи. `compose.yaml` меняется так, чтобы встроенный Caddy запускался только в своём профиле, при своём прокси журнал публиковался на `127.0.0.1:3100`, а пути папок брались из переменных со значениями по умолчанию, при которых прежний `docker compose up` работает как раньше. Затем `docker compose config`, сборка и запуск, ожидание `/healthz` до 60 секунд; при неудаче – последние строки журнала контейнера, `.env` и данные остаются, ничего не удаляется, выход с ошибкой. После успеха – проверка `https://домен/healthz`, неудача – предупреждение.

Способ входа в этом срезе не спрашивается: `.env` пишется как для личных паролей (общий пароль пустой); выбор и первый код – в таске 02.

## Критерии приёмки

- [x] `install.sh` и `install.bat` в корне запускают ядро; без Node.js 24 – подсказка и остановка (К1).
- [x] Ответы по умолчанию принимаются Enter, `<` возвращает к предыдущему вопросу с прежними ответами (К4).
- [x] Нет Docker или Compose, занят порт 80 или 443 при встроенном Caddy, плохой домен – сообщение и остановка до изменений (К3, К14).
- [x] `.env` содержит перечисленные значения, права закрыты, перевод строки в значении отклоняется, секреты не выводятся (К6).
- [x] При своём прокси Caddy не запускается, журнал на `127.0.0.1:3100`, спрошен `TRUST_PROXY`, есть предупреждение про Host (К9).
- [x] Выбранные пути папок попадают в запуск контейнеров; без переменных `docker compose up` работает как раньше (К10).
- [x] План запуска: `docker compose config`, сборка и запуск, ожидание `/healthz`; при неудаче – последние строки журнала, ничего не удаляется, выход с ошибкой (К11).
- [x] Неудачная проверка HTTPS – предупреждение, установка успешна (К12).
- [x] Тесты ядра с подменённым вводом и подменённым запуском команд проверяют всё перечисленное; существующие тесты журнала проходят.

## Заметка исполнителя

- Свой прокси выключает Caddy через `scale: ${PROXY_SCALE:-1}` в compose.yaml, а не через профиль: без переменной прежний `docker compose up` запускает Caddy, как раньше. `docker compose config` проверен с обоими значениями; живой запуск Compose с `scale: 0` на этом Mac не проверен (демон Docker не запущен).
- Журнал в контейнере теперь публикуется на `127.0.0.1:3100` хоста (только loopback) – и для своего прокси, и для проверки `/healthz` установщиком.
- Ответы читаются построчно по порядку: `readline/promises` терял строки, пришедшие до вопроса, при вводе из конвейера.
- Проверка настоящей связки `install.sh` → ядро на macOS: вопросы по порядку, остановка на «Docker не запущен», `.env` не создан.
