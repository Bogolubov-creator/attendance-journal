# 04: Прежняя установка – «Обновить» или «Выйти»

**Статус:** done

**Блокируется:** 01, 03

**Закрывает критерии:** К5

## Что построить

Если в целевой папке есть `.env` или файл базы журнала, установщик не задаёт вопросов новой установки, а предлагает «Обновить» или «Выйти». «Обновить»: копия базы с датой в имени, новый код, пересборка и перезапуск (Docker – `docker compose up -d --build`; без Docker – `npm ci --omit=dev` и перезапуск службы или задачи), затем `/healthz`; `.env`, база, сканы и резервные копии не меняются, режим входа остаётся прежним. Перезаполнить настройки можно только отдельным ключом запуска и после подтверждения; прежний `.env` сохраняется копией с датой.

## Критерии приёмки

- [x] Найденная прежняя установка – только «Обновить» или «Выйти»; «Выйти» ничего не меняет (К5).
- [x] «Обновить» в каждом локальном сценарии делает копию базы, ставит новый код и перезапускает; `.env`, база, сканы и копии не тронуты (К5).
- [x] Перезаполнение настроек – только ключом с подтверждением, прежний `.env` сохраняется копией (К5).

## Заметка исполнителя

- Enter на вопросе «Что сделать?» означает «Выйти»: обновление выбирается явно («1») или ключом `--update`. Иначе в папке владельца с рабочей базой одно нажатие запустило бы `git pull` и остановку журнала.
- Новый код при обновлении: если папка под git – `git pull --ff-only` (при ошибке – остановка до остановки журнала); без git обновляется то, что лежит в папке.
- Копия базы снимается при остановленном журнале копированием файла (и его WAL, если есть) – `sqlite3` для этого не нужен.
- Способ прежней установки угадывается по `.env` (переменные Docker), службе systemd или задаче планировщика и предлагается ответом по умолчанию.
