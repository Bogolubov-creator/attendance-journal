# 09: Проверки до изменений и навигация назад

## Что построить

Ревью 25.09, ось «Спека»:
- К3: «Права (… на Linux – не root, с sudo)» – право на sudo заранее не проверяется; `sudo chown` при Docker на Linux идёт уже после записи `.env`. Нужна проверка sudo до изменений там, где оно понадобится.
- К4: «<» не переходит между этапами вопросов: с «Адреса сайта» не вернуться к «Как ставить?», на сервере – к «Папке на сервере». Нужно, чтобы «<» возвращал к любому предыдущему вопросу, а проверки этапа повторялись при изменении ответа.
- К5: `--reconfigure` при базе без `.env` идёт без подтверждения и включает режим личных паролей на существующей базе. Нужно подтверждение и в этом случае, а режим входа на существующей базе не менять молча.
- Обновление без Docker на Windows при сбое пишет «Смотрите server.log» вместо последних строк журнала – нужны строки, как при установке.
- Поиск прежней установки смотрит базу только в `data/`, игнорируя `DATA_DIR` из `.env`.
- Ошибка `icacls` не проверяется – закрыть права нужно гарантированно или остановиться.

## Критерии приёмки

- [x] Нет права sudo на Linux – сообщение и остановка до изменений (К3).
- [x] «<» возвращает к предыдущему вопросу через границу этапов, проверки способа установки повторяются (К4).
- [x] `--reconfigure` при существующей базе без `.env` – подтверждение; режим входа существующей базы не меняется без вопроса (К5).
- [x] Обновление без Docker на Windows при сбое показывает последние строки `server.log` (К11).
- [x] Прежняя установка находится по базе в папке из `DATA_DIR`/`DB_PATH`.
- [x] Неуспешный `icacls` – остановка с сообщением.

## Заметка исполнителя

- «<» на первом вопросе этапа уводит на предыдущий этап; прежние ответы становятся ответами по умолчанию, проверки этапа (Docker, systemd, sudo, сервер по SSH) повторяются.
- При Docker на Linux папки отдаются пользователю контейнера через `docker run … chown` – sudo для этого способа больше не нужен; для способа без Docker право sudo проверяется `sudo -v` до изменений.
- Копия `.env` при перезаполнении снимается в момент записи новых настроек и сразу закрывается теми же правами (это же закрывает находку безопасности SEC-1).
