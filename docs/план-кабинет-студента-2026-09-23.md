# Личный кабинет студента: план работ

> **Для исполнителя:** обязательный под-скилл – `superpowers:subagent-driven-development` (рекомендуется) или `superpowers:executing-plans`. Шаги отмечаются галочками `- [ ]`.

**Цель:** студент входит в свой кабинет, сам заполняет обязательные требования, прикладывает сканы, правит свои документные и бытовые поля и видит свою посещаемость; занятия и учебные поля остаются за сотрудником.

**Устройство:** третья роль `student` в том же приложении. Серверная часть кабинета живёт в новом модуле `src/student.js` и подключается к `app` так же, как это делает `registerDaily` из `src/daily.js`; работа с файлами вынесена в `src/attachments.js`; политика (какие поля правит студент, кто закрывает требование) лежит в `src/office.js` рядом с остальными правилами. Интерфейс кабинета – отдельная страница `public/student.html` с `public/student.js`, чтобы не тащить студенту 68 КБ сотрудничьего `app.js`.

**Технологии:** Node.js 24, Express 5, встроенный `node:sqlite`, фронт без сборки, тесты `node:test` + jsdom. Новых зависимостей не добавляем: файлы принимаются `express.raw`, как уже сделано для импорта реестра в `src/server.js:456`.

**Спецификация:** `docs/кабинет-студента-2026-09-23.md` – читать вместе с планом.

## Общие ограничения

- Node.js 24, `"type": "module"`, Express 5, `node:sqlite`. Новых зависимостей в `package.json` не появляется.
- Коммиты по-английски, документация и комментарии по-русски (правило владельца).
- Форматирование: `npx prettier --write` по изменённым файлам; CI гоняет `npm test` и `npm audit --omit=dev`.
- Тесты запускают сервер на своём порту. Заняты: 3101 api, 3102 и 3104 production, 3103 office, 3105 add-student, 3106 и 3107 registry, 3108 registry-update, 3109 и 3110 hosting, 3111 чистая установка, **3112 занят шлюзом рабочего сервера на Mac владельца**. Новые тесты берут 3113, 3114, 3115. Совпадение портов не роняет прогон, а вешает его навсегда.
- Тесты не трогают рабочую базу: каждый поднимает сервер с `DB_PATH` во временной папке и `ROSTER_PATH: "tests/fixtures/roster.json"`.
- Каждое действие студента и сотрудника пишется в `audit` через существующий помощник `audit(user, action, entity, label)` (`src/server.js:119`).
- Требование по умолчанию закрывает сотрудник (`closedBy: "staff"`); список самостоятельно закрываемых владелец даст позже.
- Кабинет включается на сервере только после подключения OIDC ВШЭ. До этого вход студентом работает лишь в демонстрационном режиме.

## Что проверить особо

Пять входов, которые спецификация подразумевает, но ни один очевидный тест не трогает. Каждый закреплён за задачей.

1. **Имя файла с путём или управляющими символами** (`../../etc/passwd`, имя с `\0`, имя в 300 знаков, кириллица и эмодзи). Ожидание: файл сохраняется под именем, которое произвёл журнал; исходное имя показывается, но никуда не подставляется; выдача не ломается. – Задача 7.
2. **Осиротевшая привязка**: студента переименовали, его идентификатор изменился, `student_accounts` указывает в никуда. Ожидание: кабинет отвечает «учётная запись не связана», а не 500. – Задача 3.
3. **Одновременная правка**: студент сохраняет карточку, пока менеджер правит её же. Ожидание: 409 и ничего не перезаписано, как уже сделано у сотрудников. – Задача 4.
4. **Студент без карточки**: запись есть в реестре, а строки в `student_profiles` нет (так выглядит любой свежий импорт). Ожидание: кабинет открывается с пустыми полями, а не падает. – Задача 4.
5. **Оборванная загрузка и превышение размера**: файл больше предела или соединение разорвано на середине. Ожидание: в папке не остаётся частичного файла, в таблице – записи. – Задача 7.

// Поля карточки, которые студент правит сам. Учебные поля (программа, курс,

    typeof req.body.externalId === "string" ? req.body.externalId.trim() : "";

```js
import { createHash, randomBytes } from "node:crypto";
import { mkdirSync, writeFileSync, rmSync } from "node:fs";
import path from "node:path";

const signatures = [
  { ext: "pdf", mime: "application/pdf", magic: [0x25, 0x50, 0x44, 0x46] },
  { ext: "jpg", mime: "image/jpeg", magic: [0xff, 0xd8, 0xff] },
  {
    ext: "png",
    mime: "image/png",
    magic: [0x89, 0x50, 0x4e, 0x47, 0x0d, 0x0a, 0x1a, 0x0a],
  },
];
export function detectType(buffer) {
  return (
    signatures.find((s) => s.magic.every((byte, i) => buffer[i] === byte)) ||
    null
  );
}
// Имя на диске производит журнал: присланное имя нигде не участвует в пути.
export function saveAttachment({ dir, studentId, buffer, ext }) {
  const folder = path.join(dir, studentId);
  mkdirSync(folder, { recursive: true });
  const storedName = randomBytes(16).toString("hex") + "." + ext;
  const target = path.join(folder, storedName);
  try {
    writeFileSync(target, buffer);
  } catch (error) {
    rmSync(target, { force: true });
    throw error;
  }
  return {
    storedName,
    size: buffer.length,
    sha256: createHash("sha256").update(buffer).digest("hex"),
  };
}
export const attachmentPath = (dir, studentId, storedName) =>
  path.join(dir, studentId, storedName);
```

- [ ] **Шаг 6: реализовать маршруты**

Таблица в `src/server.js` рядом с остальными:

```sql
CREATE TABLE IF NOT EXISTS attachments(id TEXT PRIMARY KEY, studentId TEXT NOT NULL, kind TEXT NOT NULL, fileName TEXT NOT NULL, storedName TEXT NOT NULL, mime TEXT NOT NULL, size INTEGER NOT NULL, sha256 TEXT NOT NULL, uploadedAt TEXT NOT NULL, uploadedBy TEXT NOT NULL);
```

В `src/student.js`:

```js
const uploadDir = process.env.UPLOAD_DIR || "data/uploads";
// Имя от студента только показывается: в путь оно не попадает.
const cleanName = (raw) =>
  decodeURIComponent(raw || "файл")
    .replace(/[\u0000-\u001f/\\]/g, " ")
    .trim()
    .slice(0, 200) || "файл";

app.post(
  "/api/student/attachments/:kind",
  onlyStudent,
  express.raw({ type: () => true, limit: "10mb" }),
  (req, res) => {
    if (!procedureCatalog.some((c) => c.id === req.params.kind))
      throw fail(404, "Требование не найдено");
    if (!Buffer.isBuffer(req.body) || !req.body.length)
      throw fail(400, "Загрузите файл PDF, JPEG или PNG");
    const type = detectType(req.body);
    if (!type) throw fail(400, "Принимаются только PDF, JPEG и PNG");
    const count = get(
      "SELECT COUNT(*) n FROM attachments WHERE studentId=? AND kind=?",
      req.studentId,
      req.params.kind,
    ).n;
    if (count >= 10) throw fail(400, "К одному требованию не больше 10 файлов");
    const saved = saveAttachment({
      dir: uploadDir,
      studentId: req.studentId,
      buffer: req.body,
      ext: type.ext,
    });
    const id = "a_" + randomBytes(8).toString("hex");
    run(
      "INSERT INTO attachments VALUES(?,?,?,?,?,?,?,?,?,?)",
      id,
      req.studentId,
      req.params.kind,
      cleanName(req.headers["x-file-name"]),
      saved.storedName,
      type.mime,
      saved.size,
      saved.sha256,
      new Date().toISOString(),
      req.session.user.name,
    );
    audit(
      req.session.user,
      "attachment.add",
      req.studentId + ":" + req.params.kind,
    );
    res.json({ id });
  },
);

app.get("/api/attachments/:id", (req, res) => {
  const user = req.session?.user;
  if (!user) throw fail(401, "Войдите в свой кабинет");
  const row = get("SELECT * FROM attachments WHERE id=?", req.params.id);
  if (!row) throw fail(404, "Файл не найден");
  const allowed =
    user.role === "student"
      ? user.studentId === row.studentId
      : ["admin", "office"].includes(user.role) &&
        canSeeStudent(user, studentProfile(row.studentId));
  if (!allowed) throw fail(403, "Файл другого студента");
  audit(user, "attachment.view", row.studentId + ":" + row.id);
  res.set({
    "Content-Type": row.mime,
    "Cache-Control": "no-store",
    "Content-Disposition":
      "attachment; filename*=UTF-8''" + encodeURIComponent(row.fileName),
  });
  res.sendFile(
    path.resolve(attachmentPath(uploadDir, row.studentId, row.storedName)),
  );
});

app.delete("/api/student/attachments/:id", onlyStudent, (req, res) => {
  const row = get("SELECT * FROM attachments WHERE id=?", req.params.id);
  if (!row || row.studentId !== req.studentId)
    throw fail(404, "Файл не найден");
  const requirement = proceduresFor(req.studentId).find(
    (p) => p.id === row.kind,
  );
  // Подтверждённое требование студент уже не разбирает: файл снимает сотрудник.
  if (requirement.state === "confirmed")
    throw fail(403, "Требование подтверждено, обратитесь к менеджеру");
  rmSync(attachmentPath(uploadDir, row.studentId, row.storedName), {
    force: true,
  });
  run("DELETE FROM attachments WHERE id=?", req.params.id);
  audit(req.session.user, "attachment.delete", req.studentId + ":" + row.kind);
  res.json({ ok: true });
});
```

Сотрудничье удаление (`DELETE /api/admin/attachments/:id` с проверкой `editable(req, row.studentId)`) пишется тем же телом, но без ограничения по состоянию требования.

Превышение размера Express 5 отклоняет сам с кодом 413 до обработчика, поэтому частичного файла на диске не возникает: запись идёт одним `writeFileSync` уже после полной приёмки тела.
