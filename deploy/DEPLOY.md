# Развёртывание на Linux / FirstVDS

## Подготовка

Linux с Docker Engine и Compose, постоянным диском. Домен должен указывать на сервер. Для нового выделенного сервера используется Caddy из compose.yaml на портах 80/443. Если уже есть сайты, подключить приложение через существующий прокси; не занимать их порты вторым Caddy.

## Установка

Распаковать архив в отдельную папку приложения.

```sh
cp .env.example .env
mkdir -p backups
```

В `.env` указать `DOMAIN` и совпадающий `APP_ORIGIN=https://ваш-домен`. Оставить `AUTH_MODE=selection`, `DEMO_MODE=false`. Параметры OIDC и accounts.json для этого режима не нужны.

Выбор роли и ФИО не проверяет личность. Роли руководства требуют пароль, настроенный через MANAGEMENT_PASSWORD_HASH (scrypt). Если хеш не задан, вход руководства закрыт. Пароль общий для управленческих ролей и не удостоверяет личность выбранного сотрудника. HTTPS шифрует соединение, но не ограничивает посетителей. Перед размещением персональных данных определить ограниченный круг сетевого доступа к сайту; сам выбор имени этого не обеспечивает.

Контейнер работает от UID/GID 1000. Только в папке нового приложения:

```sh
sudo chown -R 1000:1000 data backups
sudo chmod 700 data backups
chmod 600 .env
docker compose config --quiet
docker compose up -d --build
docker compose ps
```

Проверка: `docker compose logs --tail=100 app`. Приложение не публикует 3100 на хост. Прокси должен сохранять Host, соответствующий APP_ORIGIN. Данные и копии сохраняются в подключённых папках. Один экземпляр приложения с SQLite; несколько независимых баз использовать нельзя.

## Первое заполнение и приёмка

1. Открыть сайт по HTTPS, выбрать преподавателя; проверить свои дисциплины и сохранность тестовой отметки после перезагрузки.
2. Выбрать менеджера; проверить его участок. Руководству заполнить программы, курсы и статус контингента по проверенному реестру.
3. В отдельной тестовой базе проверить срок процедуры, отправку на проверку и подтверждение; сверить независимость от посещаемости.
4. Проверить восстановление резервной копии в отдельном экземпляре. Настроить внешнее хранение и ротацию копий.
5. Проверить реальный телефон и ожидаемую нагрузку.

Эти проверки на FirstVDS ещё не выполнены. Локальный браузер и тесты не являются подтверждением развёртывания.

## Обновления

Сохранить резервную копию всей папки data и текущей версии приложения. Обновить исходники, затем `docker compose up -d --build`. Не удалять data и backups. Новые таблицы student_profiles и procedures создаются автоматически, старые отметки и учебные долги сохраняются.

Альтернативный режим OIDC оставлен в коде: AUTH_MODE=oidc, три OIDC_* и подтверждённая административная запись в data/accounts.json. Для выбранного проекта этот режим не используется.

## РУЗ

Журнал не обращается к РУЗ, доступ к сети ВШЭ серверу не нужен. Состав студентов и преподавателей ведётся в реестре на сайте.
