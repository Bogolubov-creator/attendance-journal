# Развёртывание на Linux / FirstVDS

Короткий путь – установщик `./install.sh` или `install.bat` (в том числе с Windows на удалённый сервер по SSH), см. [INSTALL.md](../INSTALL.md). Ниже – то же вручную.

## Подготовка

Linux с Docker Engine и Compose, постоянным диском. Домен должен указывать на сервер. Для нового выделенного сервера используется Caddy из compose.yaml на портах 80/443. Если уже есть сайты, подключить приложение через существующий прокси; не занимать их порты вторым Caddy.

## Установка

Распаковать архив в отдельную папку приложения.

```sh
cp .env.example .env
mkdir -p backups uploads
```

В `.env` указать `DOMAIN` и совпадающий `APP_ORIGIN=https://ваш-домен`. Оставить `AUTH_MODE=selection`, `DEMO_MODE=false`. Параметры OIDC и accounts.json для этого режима не нужны.

`TRUST_PROXY` – число своих прокси перед приложением. С Caddy из compose.yaml это 1; при внешнем балансировщике перед Caddy – 2. По этому значению берётся адрес посетителя из `X-Forwarded-For`: без него лимит в пять попыток пароля становится общим на всех посетителей и ошибки одного закрывают вход остальным на 15 минут. Значение больше числа настоящих прокси позволяет подделать адрес заголовком.

Выбор роли и ФИО не проверяет личность. Роли руководства требуют пароль, настроенный через MANAGEMENT_PASSWORD_HASH (scrypt). Если хеш не задан, вход руководства закрыт. Пароль общий для управленческих ролей и не удостоверяет личность выбранного сотрудника. HTTPS шифрует соединение, но не ограничивает посетителей. Перед размещением персональных данных определить ограниченный круг сетевого доступа к сайту; сам выбор имени этого не обеспечивает.

Контейнер работает от UID/GID 1000. Только в папке нового приложения:

```sh
sudo chown -R 1000:1000 data backups uploads
sudo chmod 700 data backups uploads
chmod 600 .env
docker compose config --quiet
docker compose up -d --build
docker compose ps
```

Копии базы создаются раз в сутки; хранятся последние `BACKUP_KEEP` штук (по умолчанию 14), остальные удаляются после очередной копии. Они лежат на том же диске, что и база, поэтому отдельно настроить выгрузку папки `backups` на другое хранилище.

Копия базы не содержит сканов личного кабинета студента – файлы лежат отдельно в папке `uploads` (переменная `UPLOAD_DIR`). Резервировать `uploads` отдельно от `backups` и обязательно вместе с копией базы: если восстановить только базу, записи о приложенных сканах будут указывать на отсутствующие файлы. Папка не ротируется автоматически, как `backups`, поэтому её размер нужно наблюдать самостоятельно: теоретический предел – 187 студентов × 5 требований × до 10 файлов по 10 МБ, разумный запас места на диске нужен заранее.

Личный кабинет студента нельзя включать на этом сервере, пока не подключён единый вход ВШЭ (OIDC) и вопрос о персональных данных (сканы документов) не согласован с ответственным за информационную безопасность ВШЭ. До этого момента вход студентом работает только в демонстрационном режиме (`DEMO_MODE=true`), который на рабочем сервере не включается.

Проверка: `docker compose logs --tail=100 app`. Приложение не публикует 3100 на хост. Прокси должен сохранять Host, соответствующий APP_ORIGIN. Данные и копии сохраняются в подключённых папках. Один экземпляр приложения с SQLite; несколько независимых баз использовать нельзя.

## Развёртывание без данных

На сервер уезжает только приложение. Реестр, карточки, отметки и резервные копии не переносятся: при первом запуске создаётся пустая база, и до загрузки реестра на сайте нет ни одного студента и преподавателя. Данным неоткуда взяться в образе – в контекст сборки входят только `Dockerfile`, `package.json`, `package-lock.json`, `src/` и `public/` (см. `.dockerignore`), а `COPY` переносит `src` и `public`.

На сервер не копировать: файлы `data/*.sqlite`, папку `backups`, `.env` с рабочими паролями, `work/` и рабочие выгрузки Excel.

Архив для передачи собирается из репозитория, поэтому в него попадает только то, что в нём лежит:

```sh
git archive --format=tar.gz -o ~/attendance-journal.tar.gz HEAD
```

Ни одной базы и ни одного реестра в репозитории нет; единственный файл с людьми – синтетическая фикстура тестов `tests/fixtures/roster.json` со «Студентом Первым».

Пароль для входа руководства задаётся хешем:

```sh
node scripts/password-hash.mjs
```

Скрипт спросит пароль и напечатает готовую строку `MANAGEMENT_PASSWORD_HASH=…` для `.env`; сам пароль не попадает ни в историю команд, ни в список процессов. Если на сервере нет Node.js, выполнить на своей машине и перенести строку.

Приёмка пустой установки: сайт открывается по HTTPS, вход руководства проходит, разделы «Реестр иностранных студентов» и «Сотрудники» пусты, счётчики нулевые, в папке копий появляется файл. Всё это проверяется без единой записи о людях.

Наполнение реестра, когда данные разрешат передать, идёт уже на сервере, двумя способами:

1. «Реестр иностранных студентов» → «Обновить реестр из Excel»: перед применением показывается план – кого добавит, переименует и отвяжет.
2. Вручную: сначала преподаватель в разделе «Сотрудники» → «Добавить преподавателя», затем «Добавить студента» с указанием преподавателя и дисциплины. Без хотя бы одной такой связи студент не добавляется.

## Первое заполнение и приёмка

1. Открыть сайт по HTTPS, выбрать преподавателя; проверить свои дисциплины и сохранность тестовой отметки после перезагрузки.
2. Выбрать менеджера; проверить его участок. Руководству заполнить программы, курсы и статус контингента по проверенному реестру.
3. В отдельной тестовой базе проверить срок процедуры, отправку на проверку и подтверждение; сверить независимость от посещаемости.
4. Проверить восстановление резервной копии в отдельном экземпляре. Настроить внешнее хранение и ротацию копий.
5. Проверить реальный телефон и ожидаемую нагрузку.

Эти проверки на FirstVDS ещё не выполнены. Локальный браузер и тесты не являются подтверждением развёртывания.

## Обновления

Сохранить резервную копию всей папки data и текущей версии приложения. Обновить исходники, затем `docker compose up -d --build`. Не удалять data и backups. Новые таблицы student_profiles и procedures создаются автоматически, старые отметки и учебные долги сохраняются.

Альтернативный режим OIDC оставлен в коде: AUTH_MODE=oidc, три OIDC_* и подтверждённая административная запись в data/accounts.json. Для выбранного проекта этот режим не используется.

## РУЗ

Журнал не обращается к РУЗ, доступ к сети ВШЭ серверу не нужен. Состав студентов и преподавателей ведётся в реестре на сайте.
