# Установка журнала посещаемости

Инструкция для того, кто ставит журнал на сервер: Linux или Windows, через Docker или без него. Для каждого сочетания есть скрипт, который делает установку за один запуск и задаёт несколько вопросов.

На сервер уезжает только приложение. Реестр студентов, карточки и отметки в репозиторий не входят: после установки база пустая, реестр загружается уже на сайте (раздел «После установки»).

## Какой способ выбрать

|                 | Через Docker                                     | Без Docker                                                           |
| --------------- | ------------------------------------------------ | -------------------------------------------------------------------- |
| Что ставится    | Два контейнера: журнал и Caddy                   | Node.js 24 и служба (Linux – systemd, Windows – задача планировщика) |
| HTTPS           | Caddy сам получает и продлевает сертификат       | Нужен свой HTTPS-прокси: nginx, Caddy, IIS                           |
| Подходит, когда | Сервер отдан под журнал, порты 80 и 443 свободны | На сервере уже есть сайты и прокси, или Docker не разрешён           |
| Скрипт          | `install.sh --docker` / `install.ps1 -Docker`    | `install.sh --native` / `install.ps1 -Native`                        |

На Windows-сервере для Docker нужен Docker Desktop; организациям от 250 человек он требует платной подписки. Для Windows обычно проще способ без Docker.

## Требования

- **Сервер:** 2 vCPU, 2 ГБ памяти, 20 ГБ диска плюс место под сканы документов (реально 2–6 ГБ).
- **Linux:** Ubuntu 22.04+, Debian 12+ или другой дистрибутив с systemd; пользователь с правом `sudo`.
- **Windows:** Windows Server 2019+ или Windows 10/11; PowerShell «от имени администратора». Для проверки после установки нужен `curl.exe` – он есть в системе начиная с этих версий.
- **Для способа через Docker:** Docker Engine с плагином Compose v2 (Linux) или Docker Desktop (Windows).
- **Для способа без Docker:** Node.js 24 – https://nodejs.org/ (на Linux удобно через пакеты NodeSource).
- **Сеть:** доменное имя, которое указывает на сервер (например, `journal.pravo.hse.ru`). Для Docker – открытые порты 80 и 443. Доступ к журналу стоит ограничить сетью университета или VPN: в нём персональные данные иностранных граждан.

## Получить файлы

Репозиторий закрытый: нужен доступ к нему на GitHub.

```sh
git clone https://github.com/Bogolubov-creator/attendance-journal.git
cd attendance-journal
```

Без доступа к GitHub на сервере – собрать архив на своей машине и перенести:

```sh
git archive --format=tar.gz -o attendance-journal.tar.gz HEAD
```

## Linux

Из папки журнала обычным пользователем (не root):

```sh
./scripts/install.sh            # спросит способ
./scripts/install.sh --docker   # сразу через Docker
./scripts/install.sh --native   # сразу без Docker
```

## Windows

PowerShell «от имени администратора», из папки журнала:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install.ps1            # спросит способ
powershell -ExecutionPolicy Bypass -File scripts\install.ps1 -Docker    # через Docker Desktop
powershell -ExecutionPolicy Bypass -File scripts\install.ps1 -Native    # без Docker
```

`-ExecutionPolicy Bypass` действует только на этот запуск и политику системы не меняет.

## Что делает скрипт

1. Проверяет, что всё нужное установлено (Docker или Node.js 24) и что запуск идёт из папки журнала.
2. Создаёт `.env` из `.env.example`. Спрашивает домен и прописывает рабочий режим: без демо-входа, с живыми данными, с ежедневной резервной копией (14 последних). Если `.env` уже есть, спрашивает, перезаполнять ли его; прежний файл сохраняется как `.env.bak.<дата>`.
3. Спрашивает общий пароль журнала. Он нужен только на время перехода к личным паролям; можно оставить пустым. Пароль вводится с клавиатуры и в `.env` попадает только хешем.
4. Создаёт папки данных и закрывает к ним доступ посторонним: на Linux – права 700, на Windows – доступ только администраторам и системе.
5. Запускает журнал:
   - **Docker:** `docker compose up -d --build`, ждёт, пока контейнер станет здоровым;
   - **Linux без Docker:** ставит зависимости, создаёт и запускает службу systemd `attendance-journal` с защитными настройками (журнал может писать только в свою папку `data`);
   - **Windows без Docker:** ставит зависимости, регистрирует задачу планировщика `AttendanceJournal` (запуск при старте системы от имени SYSTEM, перезапуск при сбое), запускает её.
6. Проверяет, что журнал отвечает, и печатает следующие шаги.

Повторный запуск безопасен: данные не трогаются, служба или задача пересоздаются. Этим же способом ставится обновление.

## HTTPS для способа без Docker

Журнал слушает только `127.0.0.1:3100` и в рабочем режиме открывается лишь по адресу из `APP_ORIGIN` (`https://ваш-домен`). Прокси обязан передавать заголовок `Host` без изменений; иначе журнал отвечает «Недопустимый адрес сервера».

nginx (Linux):

```nginx
server {
  listen 443 ssl;
  server_name journal.pravo.hse.ru;
  # ssl_certificate и ssl_certificate_key – сертификат домена
  client_max_body_size 30m;
  location / {
    proxy_pass http://127.0.0.1:3100;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  }
}
```

Caddy (Linux и Windows, сертификат получает сам), файл `Caddyfile`:

```
journal.pravo.hse.ru {
  reverse_proxy 127.0.0.1:3100
}
```

IIS: модули URL Rewrite и Application Request Routing, правило обратного прокси на `http://127.0.0.1:3100` с сохранением заголовка Host (`preserveHostHeader` в настройках ARR).

`client_max_body_size 30m` нужен для загрузки реестра из Excel (до 25 МБ).

## После установки

1. **Первый вход администратора журнала.** Скрипт выдаёт код приглашения:
   - Docker: `docker compose exec app node scripts/invite-admin.mjs gadzhieva`
   - без Docker: `node scripts/invite-admin.mjs gadzhieva` (из папки журнала)

   Он печатает логин и код. На сайте – «Первый вход по коду приглашения», там задаётся пароль.

2. **Реестр.** «Студенты» → «Обновить реестр из Excel»: сначала показывается план изменений, запись – после подтверждения.
3. **Доступ сотрудникам.** «Сотрудники» → «Выгрузить коды приглашения», рассылка кодов, затем «Включить вход только по личным паролям». Подробно – README, раздел «Личные пароли сотрудников».

## Резервные копии

Журнал сам копирует базу раз в сутки, хранит 14 последних копий:

|                  | Docker                   | Без Docker               |
| ---------------- | ------------------------ | ------------------------ |
| База             | `data/attendance.sqlite` | `data/attendance.sqlite` |
| Копии базы       | `backups/`               | `data/backups/`          |
| Сканы документов | `uploads/`               | `data/uploads/`          |

Копии лежат на том же диске, поэтому их нужно регулярно выгружать в другое хранилище, всегда вместе со сканами. Восстановление – остановить журнал, положить копию на место `data/attendance.sqlite`, запустить.

## Обслуживание

| Действие       | Docker                                     | Linux без Docker                               | Windows без Docker                                                         |
| -------------- | ------------------------------------------ | ---------------------------------------------- | -------------------------------------------------------------------------- |
| Состояние      | `docker compose ps`                        | `sudo systemctl status attendance-journal`     | `Get-ScheduledTask AttendanceJournal`                                      |
| Журнал сервера | `docker compose logs --tail=100 app`       | `sudo journalctl -u attendance-journal -n 100` | `data\server.log`                                                          |
| Перезапуск     | `docker compose restart app`               | `sudo systemctl restart attendance-journal`    | снова `install.ps1 -Native`                                                |
| Обновление     | `git pull`, `docker compose up -d --build` | `git pull`, `npm ci --omit=dev`, перезапуск    | `git pull`, снова `install.ps1 -Native`                                    |
| Остановить     | `docker compose down`                      | `sudo systemctl stop attendance-journal`       | `Stop-ScheduledTask AttendanceJournal` и остановить процесс `node` журнала |

## Если что-то не так

- **«Недопустимый адрес сервера» (403).** Сайт открыт не по адресу из `APP_ORIGIN`, или прокси подменяет заголовок Host.
- **Журнал не запускается, в логе «В рабочем режиме нужен APP_ORIGIN с HTTPS».** В `.env` адрес должен начинаться с `https://`.
- **Порт 3100 занят.** Поменяйте `PORT` в `.env` (без Docker) и адрес в настройке прокси.
- **Windows: «выполнение сценариев отключено».** Запускайте ровно командой из раздела «Windows», с `-ExecutionPolicy Bypass`.
- **Docker: сертификат не получен.** Домен должен указывать на сервер, порты 80 и 443 – быть открыты снаружи.

## Что нельзя класть в репозиторий

`.env`, `data/`, `backups/`, `uploads/`, выгрузки Excel и файл с кодами приглашения. В них персональные данные и секреты; `.gitignore` их уже исключает.
