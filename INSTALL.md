# Установка журнала посещаемости

Для того, кто ставит журнал: на свой компьютер, на сервер рядом или на удалённый Linux-сервер по SSH. Установщик один на Windows, Linux и macOS – вопросы и проверки везде одинаковые.

На сервер уезжает только приложение. Реестр, карточки и отметки в репозиторий не входят: после установки база пустая, реестр загружается на сайте (раздел «После установки»).

## Запуск

Из папки журнала:

| Система      | Команда                                                 |
| ------------ | ------------------------------------------------------- |
| Linux, macOS | `./install.sh`                                          |
| Windows      | `install.bat` – двойным щелчком или из командной строки |

Нужен **Node.js 24** на компьютере, где запускается установщик: https://nodejs.org/ (на Linux удобно через пакеты NodeSource). Без него `install.sh` и `install.bat` сразу подскажут, где его взять.

Прежние команды тоже работают и ведут в тот же установщик: `scripts/install.sh --docker|--native`, `powershell -ExecutionPolicy Bypass -File scripts\install.ps1 -Docker|-Native`.

Ключи запуска:

| Ключ            | Что делает                                                                       |
| --------------- | -------------------------------------------------------------------------------- |
| `--docker`      | этот компьютер, через Docker – без вопроса «куда и как»                          |
| `--native`      | этот компьютер, без Docker                                                       |
| `--update`      | при найденной установке сразу «Обновить»                                         |
| `--reconfigure` | заполнить настройки заново (с подтверждением, прежний `.env` сохраняется копией) |

## Как отвечать на вопросы

У каждого вопроса – пояснение и ответ по умолчанию в квадратных скобках: **Enter** принимает его, **`<`** возвращает к предыдущему вопросу. Выбор из списка – номером. До последнего вопроса «Установить?» ничего не меняется; ответ «н» – выход без изменений.

## Какой способ выбрать

|               | Этот компьютер через Docker                                            | Этот компьютер без Docker                                                     | Удалённый Linux-сервер по SSH                              |
| ------------- | ---------------------------------------------------------------------- | ----------------------------------------------------------------------------- | ---------------------------------------------------------- |
| Что ставится  | контейнеры журнала и Caddy                                             | Node.js-приложение как служба: Linux – systemd, Windows – задача планировщика | контейнеры журнала и Caddy на сервере                      |
| Нужно на цели | Docker Engine + Compose v2 (Linux) или Docker Desktop (Windows, macOS) | Node.js 24; Linux – systemd и sudo; Windows – права администратора            | Linux, Docker + Compose v2, пользователь в группе `docker` |
| HTTPS         | встроенный Caddy или свой прокси                                       | свой прокси                                                                   | встроенный Caddy или свой прокси                           |
| macOS         | да                                                                     | нет – только Docker                                                           | –                                                          |

Docker Desktop для организаций от 250 человек требует платной подписки; на Windows-сервере обычно проще способ без Docker.

## Вопросы установщика

1. **Куда ставить** – на этот компьютер или на удалённый Linux-сервер по SSH.
2. Для удалённого: **адрес сервера, пользователь SSH, порт** (22), **путь к ключу** (Enter – ключ по умолчанию), **папка на сервере** (`/opt/attendance-journal`). Пароль SSH, если нужен, спрашивает сам SSH; при входе по паролю он спросит его несколько раз, поэтому удобнее ключ.
3. Для этого компьютера: **через Docker или без Docker**.
4. **Адрес сайта** – домен, который указывает на сервер (например, `journal.pravo.hse.ru`); сайт открывается по `https://домен`.
5. **HTTPS** – встроенный Caddy (сам получает сертификат, занимает порты 80 и 443) или свой прокси сервера. Для своего – **сколько прокси стоит перед журналом** (`TRUST_PROXY`, обычно 1).
6. **Папки** базы, резервных копий и сканов – по умолчанию в папке журнала; можно вынести на отдельный диск.
7. **Сколько резервных копий хранить** (14).
8. **Как сотрудники входят** – личные пароли (по умолчанию) или только общий пароль (установщик предупредит, что он не подтверждает личность, спросит пароль скрыто дважды и сохранит только хеш).
9. Сводка и **«Установить?»**.
10. После запуска – **кому выдать первый код приглашения** (по умолчанию Гаджиевой).

## Что делает установщик

1. **Проверяет до изменений:** папку журнала, Docker и Compose или systemd и права, SSH-доступ, Linux и права на Docker на сервере, свободные порты 80 и 443 для Caddy. Любая ошибка – объяснение, что сделать, и остановка; ничего не изменено.
2. **Создаёт `.env`** с рабочим режимом (без демо-входа, живые данные, ежедневная копия базы) и закрывает его: права 600 на Linux и macOS, на Windows – только администраторы и система. На удалённый сервер `.env` передаётся через SSH, не появляясь на локальном диске.
3. **Готовит папки данных** с закрытыми правами (в Docker – владелец пользователь контейнера).
4. **Удалённо – копирует код** архивом только из файлов приложения: без `.env`, баз, выгрузок и копий.
5. **Запускает** – `docker compose up -d --build`, служба systemd или задача планировщика – и **ждёт ответа журнала** до 60 секунд. Если журнал не ответил – показывает последние строки его журнала; `.env` и данные остаются, ничего не удаляется.
6. **Проверяет сайт по HTTPS.** Неудача – только предупреждение: Caddy может получать сертификат несколько минут, пока домен не начал указывать на сервер.
7. **Личные пароли:** свежая установка сразу работает только по ним – общего пароля и выбора себя из списка нет. Установщик выдаёт первый код выбранному сотруднику полного доступа и показывает логин и код.
8. **Печатает памятку:** адрес, журнал сервера, перезапуск, где данные, резервные копии, следующие шаги.

## Обновление

Снова запустите установщик в той же папке (для сервера – с тем же адресом и папкой). Он найдёт прежнюю установку и предложит **«Обновить»** или **«Выйти»**; Enter – «Выйти», обновление выбирается явно («1») или ключом `--update`.

«Обновить»:

- на этом компьютере – `git pull --ff-only`, если папка под git (иначе обновляется код, который лежит в папке);
- удалённо – новый архив кода с этого компьютера;
- остановка журнала и **копия базы** рядом с ней (`attendance.before-update-<дата>.sqlite`);
- пересборка или `npm ci` и запуск, проверка ответа.

`.env`, база, сканы и резервные копии не меняются, способ входа остаётся прежним. Заполнить настройки заново – `--reconfigure`.

## Свой HTTPS-прокси

Журнал слушает только `127.0.0.1:3100` сервера и открывается лишь по адресу из `APP_ORIGIN` (`https://домен`). Прокси обязан передавать заголовок `Host` без изменений; иначе журнал отвечает «Недопустимый адрес сервера».

nginx:

```nginx
server {
  listen 443 ssl;
  server_name journal.pravo.hse.ru;
  # ssl_certificate и ssl_certificate_key – сертификат домена
  client_max_body_size 30m;
  location / {
    proxy_pass http://127.0.0.1:3100;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  }
}
```

Caddy (Linux и Windows, сертификат получает сам):

```
journal.pravo.hse.ru {
  reverse_proxy 127.0.0.1:3100
}
```

IIS: URL Rewrite и Application Request Routing, обратный прокси на `http://127.0.0.1:3100` с сохранением заголовка Host (`preserveHostHeader`).

`client_max_body_size 30m` нужен для загрузки реестра из Excel (до 25 МБ).

## После установки

1. **Первый вход.** Сотрудник, которому выдан код, открывает сайт, выбирает «Первый вход по коду приглашения» и задаёт пароль. Если код потерян – выдать новый: `node scripts/invite-admin.mjs gadzhieva` в папке журнала (если база не в `data/` – с переменной `DB_PATH`, путь к файлу базы; Docker: `docker compose exec app node scripts/invite-admin.mjs gadzhieva`).
2. **Реестр:** «Студенты» → «Обновить реестр из Excel» – сначала план изменений, запись после подтверждения.
3. **Доступ остальным:** «Сотрудники» → «Выдать доступ» по одному или «Выгрузить коды приглашения» на всех. Подробнее – README, раздел «Личные пароли сотрудников».
4. **Ограничить доступ к сайту** сетью университета или VPN: в журнале персональные данные иностранных граждан.

## Резервные копии

Журнал сам копирует базу раз в сутки и хранит заданное число копий в выбранной папке. Копии лежат на том же диске и **не включают сканы**: папку копий и папку сканов нужно регулярно выгружать на внешнее хранилище вместе. Восстановление – остановить журнал, положить копию на место `attendance.sqlite` в папке базы, запустить.

## Обслуживание

| Действие       | Docker (здесь или на сервере)        | Linux без Docker                               | Windows без Docker                    |
| -------------- | ------------------------------------ | ---------------------------------------------- | ------------------------------------- |
| Состояние      | `docker compose ps`                  | `sudo systemctl status attendance-journal`     | `Get-ScheduledTask AttendanceJournal` |
| Журнал сервера | `docker compose logs --tail=100 app` | `sudo journalctl -u attendance-journal -n 100` | `server.log` в папке базы             |
| Перезапуск     | `docker compose restart app`         | `sudo systemctl restart attendance-journal`    | установщик → «Обновить»               |
| Обновление     | установщик → «Обновить»              | установщик → «Обновить»                        | установщик → «Обновить»               |

Команды Docker выполняются в папке журнала; на удалённом сервере – после `ssh пользователь@сервер` и `cd` в папку журнала.

## Если что-то не так

- **«Нужен Node.js 24»** – установите Node.js 24 на компьютер, где запускаете установщик.
- **«Docker не запущен или у пользователя нет к нему доступа»** – запустите Docker Desktop или добавьте пользователя в группу `docker` и войдите заново.
- **«Порт 80 (443) занят»** – на сервере уже есть сайт: освободите порт или выберите «Свой прокси сервера».
- **«Нет доступа по SSH»** – проверьте адрес, порт, пользователя и ключ: `ssh -p порт пользователь@сервер`.
- **«Недопустимый адрес сервера» (403)** – сайт открыт не по адресу из `APP_ORIGIN`, или прокси подменяет заголовок Host.
- **Журнал не ответил за 60 секунд** – последние строки его журнала уже на экране; чаще всего это ошибка в `.env` или занятый порт 3100.
- **Windows: «запустите от имени администратора»** – для способа без Docker откройте командную строку или PowerShell «от имени администратора».
- **macOS без Docker** – не поддерживается, выберите «Через Docker».

## Что нельзя класть в репозиторий

`.env`, папки данных, резервных копий и сканов, выгрузки Excel, файл с кодами приглашения. В них персональные данные и секреты; `.gitignore` их исключает, а архив для сервера собирается только из файлов приложения.
